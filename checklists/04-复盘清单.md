# 04 复盘清单

> 每月一次，或每次线上事故后执行。目标不是总结，是让下一次更省力。

## 事实

- [ ] 列出本期所有线上 bad case（含时间、输入摘要、错误输出）
- [ ] 按 提示 / 工具 / 检索 / 模型 / 数据 五类归因，统计分布
- [ ] 记录指标：成功率、误答率、p95 延迟、单次成本、人工修正率
- [ ] 与上期对比，写出变化方向

## 沉淀

- [ ] 每个 bad case 已转成 eval 用例（脱敏后入库）
- [ ] 新踩的坑写进 `docs/06-反模式与速查.md`（若具通用性）
- [ ] 重复出现的操作已抽成脚本
- [ ] 失效的用例已删除或修改，并说明原因
- [ ] 基线已更新

## 改进

- [ ] 只选**一个**最值得改的点，写清：假设 → 改法 → 怎么验证
- [ ] 明确不做的改进，写出理由（避免下次重新讨论）
- [ ] 更新 `docs/design.md` 中已过时的假设

## 清理

- [ ] 删除临时脚本、实验分支、废弃配置
- [ ] 检查有没有遗留的调试输出、硬编码路径
- [ ] `.env` 与密钥有效期检查
