# 01 立项清单

> 目标：用半天时间判断“该不该做”。任何一项没勾，不要进入设计阶段。

## 需求

- [ ] 需求卡五问全部作答（谁用 / 怎么触发 / 输入 / 输出判据 / 错误代价）
- [ ] 能用一句话说清：当 <触发> 时，把 <输入> 变成 <输出>
- [ ] 收集到 ≥5 条**真实**输入，含 ≥1 条边界输入
- [ ] 成功判据可量化（有数字、有测试方法），没有“效果好”这类词
- [ ] 写了明确的“非目标”（本版不做的事）

## 形态

- [ ] 已对照 `docs/03-形态适配指南.md` 第 0 节选形态
- [ ] 能回答“为什么不用更轻的形态”（为什么不做成 Skill/用现成 MCP）

## 现实约束

- [ ] 依赖的外部服务/数据源已确认可用（能拿到数据、有权限）
- [ ] 涉及敏感数据时，已明确脱敏方式
- [ ] 涉及写操作时，已明确确认/dry-run 方案
- [ ] 估算过成本量级（单次 token、每天调用次数）

## 风险

- [ ] 写下了“最可能失败的地方”，以及失败了怎么知道
- [ ] 如果是实验性质，写明“可弃用条件”（什么情况下直接放弃）

## 决策

- [ ] 做 → 进入设计阶段，产出 `docs/design.md` 与 `docs/contract.md`
- [ ] 不做 → 记录原因，归档需求卡
