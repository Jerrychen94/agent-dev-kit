# 02 开发清单

> 覆盖设计、最小链路、评测三个阶段。开发结束时全部勾选。

## 设计

- [ ] `docs/design.md` 画出了流程（步骤 × 用模型还是代码）
- [ ] `docs/contract.md` 写了输入、输出、错误码、边界
- [ ] 工具数 ≤7，每个工具都有真实使用场景
- [ ] 每个工具写清了：输入、输出、失败返回、是否幂等
- [ ] 失败表填了（超时/空结果/工具报错/输入超长/拒答）
- [ ] 写下了“明确不做”的边界
- [ ] 影响维护的决策写成了 ADR（`docs/adr/`）

## 最小链路

- [ ] 一条命令能跑通（`make run` 或等价命令），写进 README
- [ ] 至少经过一次真实模型调用和一个真实数据源/工具
- [ ] 输出是结构化 JSON，字段名与契约一致
- [ ] 失败时显式报错（有 code、message、hint），不静默返回空
- [ ] 日志是行分隔 JSON，含 `trace_id`、`step`、`duration_ms`、token 用量
- [ ] 3 条 smoke 用例在 `evals/cases/`，一条命令跑完
- [ ] 换机器按 README 能在 15 分钟内跑起来

## 代码

- [ ] 提示词在 `prompts/`，不与业务代码混写
- [ ] 配置走环境变量，代码里无硬编码密钥与绝对路径
- [ ] 没有 `except: pass`，错误带上下文向上抛
- [ ] 外部调用有超时；重试有次数上限
- [ ] 工具函数有单元测试（不调用模型）
- [ ] 新增依赖写进 README/requirements 并锁版本

## 评测

- [ ] 用例 ≥30 条，`id` 唯一，`tags` 完整
- [ ] 分层：简单/正常/困难/负例，负例与边界合计 ≥20%
- [ ] 用例与调试样例不同源
- [ ] 判分以确定性断言为主；用 judge 时已人工对齐 ≥20 条
- [ ] 基线已生成（`--update-baseline`）
- [ ] 查回退时用 `--report` 留快照；快照不入库（`.gitignore` 已挡 `evals/runs/`）
- [ ] 误差分析表：失败按 提示/工具/检索/模型/数据 归因
- [ ] CHANGELOG 记录了本轮指标变化

## 自检

```bash
make test && make evals && make check
```
