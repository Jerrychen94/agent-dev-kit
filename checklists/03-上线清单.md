# 03 上线清单

> 逐条勾，不可“跳过后补”。任何一条空着，就不上线。

## 质量

- [ ] 全量评测通过率达标（记录数值：____%）
- [ ] 负例全部按约定拒答，无崩溃
- [ ] 连续两次运行通过率波动 ≤5 个百分点
- [ ] `evals/baseline.json` 已提交
- [ ] 人工抽检 ≥20 条真实输入，记录判错原因
- [ ] CHANGELOG 写明本次变更、原因、指标变化

## 安全

- [ ] 密钥走环境变量，`.env` 在 `.gitignore` 中
- [ ] `git diff` 无密钥残留（`sk-`、`ghp_`、`AKIA`、私钥）
- [ ] 密钥权限最小化（只读够用就不给写）
- [ ] 日志不含密钥、完整手机号、身份证等敏感信息
- [ ] 输入含 PII 时已脱敏或已确认授权
- [ ] 写操作有确认或 `--dry-run`，且有幂等键
- [ ] 批量操作有单次上限

## 成本与稳定

- [ ] 单次 token 有上限（输入/输出分别限制）
- [ ] 日成本上限已设，超限熔断
- [ ] 重试限次数 + 退避，不会无限循环
- [ ] 外部调用有超时，超时返回可重试错误
- [ ] 依赖锁版本，环境可复现

## 可观测

- [ ] 日志可按 `trace_id` 还原一次完整调用
- [ ] 记录 model、输入/输出 token、耗时
- [ ] 错误按 code 可分组统计
- [ ] 关键失败（成本超限、连续失败）有告警或至少日报可见

## 运维

- [ ] `docs/runbook.md` 写了启动、停止、常见故障处理
- [ ] 回滚命令一条可执行，并**演练过一次**
- [ ] 上一个可用版本号已记录
- [ ] 读过一个真实 trace 的日志，确认能定位问题

## 发布

- [ ] 发布说明（`templates/发布说明.md`）已填
- [ ] 灰度计划：范围 ____，观察期 ____
- [ ] 上线后验证：跑 3 条 smoke、观察错误率 24 小时、抽查 5 条真实输出、确认成本在预算内

## 最后

- [ ] 负责人知道“出问题先关掉它”的具体操作
