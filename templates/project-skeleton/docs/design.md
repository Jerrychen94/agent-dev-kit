# 设计文档：invoice-field-extractor

## 1. 目标与非目标

**目标**：从一段中文发票/账单文本中抽取金额、日期、供应商三个字段，输出结构化 JSON。

**非目标**：

- 不做 OCR（输入已是文本）。
- 不做发票真伪校验。
- 不支持多币种换算。

## 2. 形态选型

- [x] Skill 工作流
- [x] 独立 LLM 应用（当前为 CLI）
- [ ] MCP Server
- [ ] 多 agent

理由：单步抽取任务，不需要服务化，也不需要拆分角色。先用 CLI 验证质量，稳定后再考虑包成 MCP 工具。

## 3. 流程

```
stdin 文本 → 规范化 → 判断是否发票 → 抽取三字段 → 校验 → stdout JSON
```

| 步骤 | 做什么 | 用模型还是代码 | 输入 | 输出 |
|---|---|---|---|---|
| 1 | 读入并判断类型 | 代码 | 原始文本 | 文本或错误 |
| 2 | 字段抽取 | 模型（当前为规则占位） | 文本 | 三字段 |
| 3 | 格式校验与补警告 | 代码 | 三字段 | 结果对象 |

## 6. 上下文与知识

- 稳定规则：输出 schema、字段定义，放系统提示。
- 变化数据：无。
- 长文本：超过 8000 字先分段，只取含“金额/发票”关键字的段落。

## 7. 失败处理

| 失败情形 | 检测方式 | 对外表现 | 是否重试 |
|---|---|---|---|
| 空输入 | strip 后为空 | `EMPTY_INPUT` | 否 |
| 非发票文本 | 无发票关键词 | `NO_INVOICE` | 否 |
| 缺金额 | 抽取结果为 None | `MISSING_AMOUNT` | 否 |
| 缺日期/供应商 | 抽取结果为 None | 成功 + warnings | 否 |
| 模型超时 | 请求超时 | `UPSTREAM_TIMEOUT` | 是，最多 2 次 |

## 8. 评测方案

- 来源：真实发票样例 20 条 + 构造边界 10 条 + 负例 5 条。
- 判分：JSON 字段精确比对（确定性断言）。
- 阈值：金额 100%、日期 95%、供应商 90%，负例 100% 正确拒答。

## 9. 成本与性能预算

- 单次 token：输入 ≤ 1500，输出 ≤ 200。
- 单次成本 ≤ 0.01 元。
- p95 延迟 ≤ 3 秒。

## 10. 风险与未知

| 假设 | 怎么验证 | 如果错了怎么办 |
|---|---|---|
| 文本中金额只出现一次 | 统计 30 条样例 | 多条金额时取“合计”后的值，否则标 warning |
| 日期格式以年月日为主 | 同上 | 增加格式分支 |
